§ 01 · How it works

Context that outlives the session.

edgemem is a thin layer between your team and Claude Code. Memory lives in Supermemory cloud. Developers share the same container. The agent reads and writes it live — no commits, no copy-pasting.

QUICK START · bash
# 1. install
npm install -g edgemem

# 2. configure
export SUPERMEMORY_API_KEY=sm-...
export EDGEMEM_CONTAINER=myproject-team

# 3. write your first memory
npx edgemem write "memory/stack.md" "
Database: PostgreSQL 16
ORM: Drizzle (not Prisma)
Package manager: pnpm
Framework: Next.js App Router
"

# 4. start Claude — it already knows
npx edgemem sync
claude

Every teammate with the same SUPERMEMORY_API_KEY gets the same context immediately. No git push. No Slack message. No onboarding doc that goes stale.

§ 02 · Delivery modes

Three ways to give
Claude the context.

All three modes share the same Supermemory container — one source of truth. Mix and match, or pick one and commit.

MODE 01
File sync
edgemem sync pulls files locally. Reference them via @import in CLAUDE.md. Simplest setup to get started.
getting started
MODE 02
MCP server
Claude gets 5 live tools: mem_read, mem_write, mem_grep and more. Reads and writes during the session.
recommended
MODE 03
Hook injection
Memory injected automatically at session start. No commands. No prompting. Always-on, zero effort.
zero effort

§ 05 · Offline resilience

If Supermemory is unreachable,
Claude Code never crashes.

edgemem falls back to local cache transparently. Cache lives at ~/.edgemem/cache/<container>/.

OperationOffline behavior
readReturns latest cached version + warns to stderr
write / appendWrites to local cache + warns to stderr, syncs when online
grepReturns empty string + warns to stderr
listReturns empty array

§ 06 · Smart context chunking

Semantic search that never floods
the context window.

mem_grep runs semantic search then returns only the relevant sections. A large memory file never fills Claude's context.

STEP 01
Split
Document split into sections by heading or paragraph
STEP 02
Score
Each section scored by query relevance. Heading match = 3×
STEP 03
Budget
Top sections returned within a 4,000-token budget
STEP 04
Warn
Warning prepended when sections are dropped from output
